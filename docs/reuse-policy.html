Documentation / Reuse policy

Reuse the contract, not just the screenshot.

Adaptations must preserve truthful time geometry, input parity, lifecycle cleanup, and the synthetic-data boundary.

Synthetic-only fixtures

Repository fixtures and screenshots must remain obviously fictional. Do not add customer or account names, quota or local-monitor language, real identifiers, copied payloads, credentials, or operational records.

Geometry before color

Do not use color as the only grouping signal. Preserve proportional placement, marker-axis alignment, structural spacing, label lanes, and readable ordering when themes change.

Interaction parity

Reusable interactive renderers must retain pointer, touch, keyboard, focus, preview, and selection behavior. New commands must appear in contextual Keyboard help.

Lifecycle ownership

Keep inputs immutable, preserve compatible state through update(), and release listeners, observers, pointer behavior, and generated DOM through destroy().
